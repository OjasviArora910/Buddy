# Memory engine

Memory is off by default and only becomes available after a user opts in. Disabling it stops retrieval; the user can separately delete all saved memories. Sensitive manual memories require an additional explicit consent checkbox and are excluded from chat retrieval. Memories expire when their selected retention time passes. Manual CRUD and basic PostgreSQL retrieval are implemented with per-user filters and active/expiry checks.

Extraction runs inline after successful account chat commits (best effort; a process crash can skip extraction). Gemini returns structured Pydantic-validated candidates with user-text evidence quotes, category, sensitivity, confidence and optional event date. Candidates without an exact evidence quote, below the confidence threshold, duplicative, contradictory without an explicit correction, expired, sensitive, or lacking opt-in are not automatically stored. Sensitive candidates are returned as suggestions for explicit user approval. Automatic storage is capped per user; source conversation, evidence reason, timestamps and expiry are persisted. Event/open-thread memories may trigger a follow-up only on a greeting, only after their due date, and at most once per user per week; sensitive facts are excluded and the memory is marked as followed up.

Retrieval first filters by verified user, active status, non-sensitive consent, and expiry. With `PGVECTOR_ENABLED=true` and the extension plus `memory_embeddings` table confirmed present, 768-dimension `gemini-embedding-001` vectors use pgvector cosine distance and metadata overlap/recency scoring. Otherwise the app uses lexical overlap and recency without reading or writing the vector table, then adds at most five facts as untrusted Gemini context. The vector migration is optional revision `0004_pgvector`; the normal local schema ends at `0003_memory_metadata`. Install pgvector and successfully apply `alembic upgrade 0004_pgvector` before enabling the flag. Saved conversation history remains separate from long-term memories.

# Buddy — internal prototype

A calm AI emotional-support companion with **Quick Chat** (no account and no server persistence of chat) and **Your Buddy** (Supabase login, saved history, user-controlled memory). Next.js frontend, FastAPI backend, Gemini model.

**Important:** This is an internal engineering prototype, **not** a clinically reviewed or production-ready mental-health application. Do not deploy to vulnerable public users. The current risk detection is a simple keyword fallback, not comprehensive. Memory extraction is an AI suggestion, not a reliable or clinically reviewed classifier; review each suggestion and do not save details you do not want processed by Gemini. Voice input uses browser speech recognition where supported, which may process speech through browser/vendor services. Do not make a zero-retention promise about third-party model or speech providers.

## Start locally

1. Create a Supabase project and run `backend/schema.sql` in its SQL editor before using account chat or memory. Enable email/password auth; email confirmation is required by default. In Supabase Auth URL Configuration, allow `http://localhost:3000/chat?mode=account` and your deployed account-chat URL as redirects. Enable Google auth and configure its provider credentials before using Google sign-in.
2. `cp backend/.env.example backend/.env` and fill in the Gemini key, Supabase URL and Supabase anon/publishable key. Account database requests use the verified user's JWT and row-level security; an optional **service role key** may be configured backend-only. The backend defaults to `GEMINI_MODEL=gemini-2.5-flash`; use a model ID supported by your Gemini API account if you override it. The backend loads this file on startup; restart it after changing settings.
3. `cd backend && python -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt && uvicorn app.main:app --reload --port 8000` (on Windows use `.venv\\Scripts\\activate`).
4. `cp frontend/.env.example frontend/.env.local` and fill in the Supabase URL and **anon/publishable** key if using a different project. `cd frontend && npm install && npm run dev`.
5. Open http://localhost:3000. Choose Quick Chat or Your Buddy. Use `127.0.0.1` or `localhost` consistently; the frontend matches its local API hostname and the backend allows both loopback origins.

## Deployment plan

- Frontend: Vercel. Set `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- Backend: Render or other Python hosting. Set `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_EMBEDDING_MODEL`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `CORS_ORIGINS`. An optional service-role key must remain backend-only.
- Database/Auth: Supabase. Set Google OAuth and correct redirect domains.
- Never expose service role or Gemini API keys in `NEXT_PUBLIC_*` variables.

## Data handling caveats

Quick Chat is not persisted by the Buddy backend, but messages go to Gemini for inference and pass through the same keyword-based crisis fallback. Account messages are stored in Supabase; relevant active memories are semantically retrieved and included in prompts. Memory extraction uses Gemini after account replies; useful non-sensitive memories may be saved automatically, while sensitive facts are only surfaced for explicit approval. Review, correct, or delete memories in What Buddy Remembers. Saved memory embeddings are generated by Gemini. Expired memories are excluded from retrieval and permanently pruned daily by Supabase pg_cron (and on the user's next account request). No promise is made about third-party logs or retention. Restrict access to trusted internal adult testers and use fictional test scenarios until privacy and clinical reviews are complete.
